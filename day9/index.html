Day 9 · 30 Day Challenge

One instruction per edit

🖌️ See the redesign
A UX teardown of PAM · editing an image

Your feedback arrives all at once. PAM takes it one note at a time.

PAM's image editor is genuinely capable — paint a region, Smart-select, one clean saved version per Apply, everything recoverable. But it takes one instruction per Apply. Real feedback is multi-point — "make her older, swap the star icon, drop the second logo" — so a single review turns into three sequential rounds. This is that flow taken apart, fairly, and a redesign that collects every note and applies them in one pass.

01

The flow, and the promise it makes

You finish a poster and someone reviews it. Real review is never one note — it's a handful of small, different fixes on the same image: change a person, swap an icon, remove a stray logo. The mental model everyone brings from Figma or a PDF markup is: drop all the comments, then apply them together. That is the promise "edit this image" quietly makes.

Credit where due. PAM's editor already does the hard parts well — a real Paint / Erase / Smart-select mask, an adjustable brush, region-scoped edits, and a clean version history where each Apply saves exactly one recoverable version. Nothing here is broken. The critique is about one missing shape, not a pile of bugs.
02

Current state — one box, one Apply

Open an image at full size and hit Edit. The "Edit artifact" window is well built — but look at the right rail: there is exactly one "What should change?" box and one "Apply edit" button. A painted mask can cover many spots, yet the whole mask receives the same single instruction. So three different fixes cannot share one Apply.

03

Diagnosis — where single-point editing bites

The honest question isn't "is batch editing good?" — it's "how often does a review carry several different notes on one image?" When it does, the cost is real: N sequential Apply rounds, each waiting on a full generate, each rebuilding on the last, with no way to see the set as one change. When it doesn't, PAM's isolated one-at-a-time model is the safer, cleaner choice.

When it hurts most
Stakeholder reviewOne person leaves 3–5 different notes on one poster at once — the everyday case.
Independent local fixesChange a face, an icon, a logo — unrelated regions that don't need to be done in order.
Deadline batchesTen posters, each with two tweaks — the round-trips multiply fast.
When one-at-a-time is right
A single fixOnly one thing to change — the extra machinery would just be in the way.
Dependent steps"Redraw the sky, then relight the scene" — the second edit needs the first to exist.
Careful isolationA risky change you want to judge — and undo — completely on its own.
A pocket rule for severity: pain ≈ notes-per-review × generate-latency × review-frequency. For a solo tweak it's ~0; for an agency shipping reviewed posters all day, it stacks into real minutes and real context-switching.
04

The redesign — One for All

One click, for all your changes. The idea barely touches the UI you already saw above: add a colour palette. Paint each change in its own colour, describe each colour, then apply them all in a single pass — landing one new version. Same Paint / Erase / Smart tools, same clean versioning; the only new primitive is a colour, which lets one Apply carry many region-scoped instructions.

The one line that keeps PAM's principle. This is not "throw a paragraph of changes into one prompt" — the thing the docs rightly warn against. Each colour stays scoped to its own region and its own instruction. We only change when they run: together, in one Apply, instead of one reopen-and-remask cycle each.

05

What this does not fix — the honest cost

A redesign that oversells itself is worse than the problem. Here is what batching genuinely does not buy you.

Model quality is unchanged

Applying together doesn't make the model render better. If a single edit looked off before, it will look off inside a batch too.

Batching can trade off reliability

Isolated edits are easier to get right. That's why we keep a per-change diff and let the agent apply pins sequentially under the hood — one review on the surface, still-isolated changes underneath.

Dependent edits still need order

"Redraw the sky, then relight it" is not a batch — it's a sequence. The canvas is for independent notes; ordered work stays one-at-a-time, and rightly so.

Net. PAM's editor is already good; this closes the one seam where everyday multi-point review leaks time. The win is honest — fewer round-trips and a verifiable result — not a claim that the editor was broken.
